# AI Clip Maker

Длинное видео → Gemini находит законченные интересные моменты → FFmpeg режет каждый в отдельный MP4 (9:16 / 1:1 / 16:9, с субтитрами).

## Как это работает
1. Источник: файл с телефона/компьютера, ссылка на YouTube (yt-dlp) или прямая ссылка на видеофайл.
2. FFmpeg извлекает аудио кусками по 5 минут → **Gemini** распознаёт речь с таймкодами (на уровне фраз).
3. Транскрипт отправляется в **Gemini**: он выбирает моменты под выбранный тип, оценивает их; границы выравниваются по фразам.
4. FFmpeg вырезает/кадрирует/кодирует каждый клип и вжигает субтитры.
5. Прогресс идёт по SSE (реальные события сервера). Проекты хранятся в `DATA_DIR`.

## Запуск локально
Нужны Node ≥ 20.10, ffmpeg, ffprobe (для YouTube — yt-dlp).
```
cp .env.example .env   # впишите GEMINI_API_KEY
node --env-file=.env server.js
npm test               # e2e без ключей: использует локальный мок Gemini
```

## yt-dlp
Устанавливается при каждой сборке: в Docker — официальный standalone-файл в `/usr/local/bin/yt-dlp` (сборка падает, если он не запускается); в обычном Node-окружении `npm install` запускает `scripts/install-bin.mjs`, который кладёт его в `./bin/yt-dlp`. Сервер при старте проверяет версию (в логе: `yt-dlp <версия> (<путь>)`), статус виден в `GET /api/config` → `ytdlp`.

## Render
Тип сервиса — **Docker** (Dockerfile в корне). Переменная `GEMINI_API_KEY` в Environment. Для сохранения проектов после перезапуска — Persistent Disk на `/data` (платный план). См. render.yaml.

## Ограничения
- Слова для «караоке»-субтитров распределяются внутри фразы пропорционально длине слов (Gemini отдаёт время фраз, а не слов).
- Анализ только по речи (без визуального анализа сцен); кадрирование без трекинга лица (центр/слева/справа).
- Хранение в JSON-файлах на диске, очередь в памяти процесса; объектное хранилище (S3/R2) не подключено.
- YouTube с серверов часто блокирует загрузку; обход защиты не выполняется — в этом случае загрузите файл.
